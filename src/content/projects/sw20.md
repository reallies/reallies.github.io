## 문제

다우기술이 제시한 과제는 **기존 문자 발송 서비스에 생성형 AI 기능을 추가하는 것**이었다. 다우기술은 코스닥 상장 IT기업으로, API 계정과 개발 가이드·샘플 코드·Swagger 문서를 제공했다.

기업이 제시한 개발 영역도 나뉘어 있었다. 프롬프트 엔지니어링과 AI 문구·이미지 생성은 학생이 다루고, 문자 발송 API부터 통신사 API까지는 기존 시스템을 그대로 쓰는 구조였다.

초기 기획제안서는 생성형 AI 포토 문자를 다뤘다. 생성 이미지에 문자·숫자가 섞이고 본문과 어울리지 않는 문제가 있었고, 이미지 후처리와 여러 장 생성 후 선정을 해법으로 검토했다. 기술안에는 Palm2 fine-tuning을 두었다.

최종 주제에서는 온라인 편집샵의 광고 문자가 단순 할인 정보에 의존한다는 문제를 잡았다. 현재 날씨에 맞는 스타일링을 제안해 광고 문자의 내용을 바꾸는 방향으로 좁혔다.

## 조사·기획

기존 문자 마케팅 사례를 수집하고 어떤 개선 방안이 있을지 살폈다. 사용자 행동이 어떻게 흘러가는지도 살폈다.

초기 안을 검토하면서 당시 이미지 생성 모델들의 성능과 한계를 조사했다. 교수에게는 이미지 생성 모델이 이미지 안의 문자를 일그러뜨리는 현상에 대한 설명을 들었다.

생성 이미지 위에 글자를 다시 덧붙이는 방식도 시도했다. 그러나 이미지마다 달라지는 위치와 배치를 맞출 해법을 찾지 못했다. 범용 이미지 품질 문제를 계속 다루기보다 사용 목적을 좁힐 필요가 있다고 판단했다.

새 주제에서는 기상청 API의 날씨 정보를 스타일링 조건으로 사용했다. 날씨와 계절에 맞춰 프롬프트를 만들고 이미지를 생성한 뒤 기존 포토문자 발송 흐름에 연결하는 구조를 잡았다.

## 내린 결정

- **날씨 맞춤 스타일링 추천으로 주제를 바꿨다**\
  첫 기획의 이미지 품질 문제를 계속 붙들지 않고 **날씨 맞춤 스타일링 추천**으로 주제를 바꿨다. 생성형 AI가 필요한 범위를 특정 용도에 맞춰 줄이고, 기업이 제공한 발송 영역은 수정하지 않았다.
- **기존 발송 서비스 앞에 생성 단계를 붙였다**\
  최종 구조는 `날씨·계절 → 프롬프트 → 이미지 → 포토문자 발송`으로 정했다. AI 생성 단계를 기존 문자 발송 서비스 앞에 붙여 기업의 기존 시스템 경계를 유지했다.
- **이미지 속 글자 섞임을 줄였다**\
  새 주제에서도 생성 이미지에 불필요한 문자·숫자·기호가 섞이는 문제가 있었다. 팀에서는 이미지에 글자를 출력하지 않도록 프롬프트에 지시하는 방식으로 수정했다. 이후 이상한 글자가 거의 나오지 않게 됐다.

## 프로젝트 구현

5인 팀 팀장으로 기획을 맡고 개발에서는 MySQL(mysql2)+SQLite 데이터베이스를 맡았다. 기존 문자 마케팅 사례와 사용자 행동 흐름을 조사했다.

프로젝트에서 구현한 내용은 다음과 같다.

- **AI 이미지 생성 파이프라인**: 날씨·계절 정보를 받아 프롬프트를 만들고 DALL·E 이미지를 생성했다. 관련 코드는 `generatePrompt.js`·`seasonalprompt.js`·`openAI_Image.js`에 구성했다.
- **프롬프트 엔지니어링**: 생성 이미지에 불필요한 문자·숫자가 섞이는 품질 문제를 프롬프트로 줄였다.
- **패션 아이템 선택 로직**과 **포토문자 발송·주소록 관리**를 구현했다. 발송과 연락처 관련 코드는 `routes/message.js`·`contacts.js`에 두었다.

## 결과

날씨에 맞는 광고 이미지를 자동 생성해 포토문자로 보내는 서비스를 구현했다. 연계 기업의 발송 API는 그대로 두고 앞단의 생성형 AI 기능을 연결했다.

초기 생성형 AI 포토 문자에서 날씨 기반 스타일링 추천으로 주제를 변경했다.

# 💼 GeNova — AI 스토리보드 빌더 (KX엔터테인먼트 인턴십)

> **6인·5주·주 15시간 제약에서 '올인원 플랫폼' 요구를 범위에서 잘라내고 배포까지 끌고 간 PM**
> `PM(2인 중 1인) · 스코프·문서 거버넌스` · `6인팀` · `2026.06–07` · 💼 첫 기업 실무

## 🎯 문제

방송·영상 제작에서 기획(텍스트)과 영상 생성 AI 사이에 사람이 매번 손으로 채우는 구간이 있다 — 콘티를 구성하고 컷마다 영문 프롬프트를 쓰는 일이다. 캐릭터·배경 일관성이 생성 모델의 한계로 무너지는 것이 현장의 가장 큰 불편이었다.

```
기획(텍스트) → [ GeNova ] → 영상 AI → 편집·음악·자막
                   ↓
     3×3 그리드 스토리보드 1장 + 통합 영문 프롬프트
```

## 🧭 내가 내린 결정

- **범위를 잘랐다** — 킥오프에서 여러 기능을 하나로 묶는 '올인원 플랫폼' 요구가 있었으나, 6명·5주·1인 주 15시간이라는 조건에서 통합을 시도하면 코드 규모만 커지고 완성도가 무너진다고 판단했다. 스토리보드와 캔버스를 독립 제품으로 다시 나눠 명시적으로 범위에서 제외하고, **디자인 시스템만 전 팀 공통으로 통일**해 향후 통합 여지를 남겼다.
- **MVP 완벽주의를 자제시켰다** — 캔버스 배치안 투표에서 가장 복잡한 안이 최다 득표였으나, 기간 내 완주 가능성을 근거로 최소안 채택을 설득하고 나머지는 로드맵으로 넘겼다.
- **무효가 될 실험을 차단했다** — 참고 이미지를 넣었을 때와 넣지 않았을 때를 비교하기로 한 날, 실행 전에 코드를 확인하다 **프론트와 백엔드의 필드명이 달라 이미지가 애초에 서버에 도달하지 않는다**는 것을 발견했다. 그대로 진행했다면 양쪽 모두 '이미지 없음' 조건이 되어 아무 의미 없는 결과로 제품 방향을 정할 뻔했다. 필드명을 맞춘 뒤 실험을 다시 설계했다.
- **못 고치는 것은 서사로 전환했다** — 컷 간 일관성·병렬 생성 문제는 기간 내 해결이 불가능했다. 원인을 코드 수준으로 규명해 로드맵과 Q&A 방어선으로 정리했다.

## 📄 문서 거버넌스

- **PRD v0.4 → v2.0 버전 체인** — 결정이 흐려지지 않도록 버전마다 무엇이 왜 바뀌었는지 남겼다. 정정 이력도 포함한다: 백엔드 스택 변경 반영 누락분, **실제 코드와 대조해 잡아낸 존재하지 않는 모델명**.
- **운영 리듬** — 데일리 회의록(결정 + 커밋/이슈 동기화) → 수정요구사항 핸드오프 문서 → 개발 전달 체계. 회의록 28건.
- **인계** — PD 요청에 제출 범위를 먼저 확정한 뒤 문서 6종을 작성하고, 미해결 사항을 '인계 시점 조치'와 '재배포 시점 과제'로 분류했다.

## 💡 배운 점

시간이 없을수록 PM이 할 일은 **자를 것을 정하고, 검증이 유효한지 먼저 확인하는 것**이었다. 코드를 읽는 능력은 개발 속도보다 **의사결정의 정확도**로 돌아왔다. 필드명 하나를 확인하지 않았다면 팀 전체가 잘못된 근거로 방향을 정했을 것이다.

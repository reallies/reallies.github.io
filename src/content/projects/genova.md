# GeNova — AI 스토리보드 빌더 (로켓단 인턴십 · KX엔터테인먼트 과제)

> **6인·5주·주 15시간 제약에서 '올인원 플랫폼' 요구를 범위에서 제외하고 배포까지 관리한 PM**

## 문제

방송·영상 제작에서 기획(텍스트)과 영상 생성 AI 사이에 사람이 매번 손으로 채우는 구간이 있다. 콘티를 구성하고 컷마다 영문 프롬프트를 쓰는 일이다.

캐릭터·배경 일관성이 생성 모델의 한계로 무너지는 것이 현장의 가장 큰 불편이었다.

```text
기획(텍스트) → [ GeNova ] → 영상 AI → 편집·음악·자막
                   ↓
     3×3 그리드 스토리보드 1장 + 통합 영문 프롬프트
```

## 조사·기획

현업 PD와 함께 필요한 기능과 범위를 정리하고 아이디어를 냈다. PM 2명 중 1명으로 PRD를 작성하고, 개발 범위와 다음 단계로 넘길 항목을 구분했다.

프로젝트 조건은 6명·5주·1인 주 15시간이었다. 킥오프에서는 여러 기능을 하나로 묶는 올인원 플랫폼 요구가 있었고, 기간 안에서 어떤 기능까지 구현할지 먼저 정리해야 했다.

## 내린 결정

- **범위를 잘랐다**: 여러 기능을 하나로 묶으면 코드 규모가 커지고 기간 내 완주가 어렵다고 판단했다. 스토리보드와 캔버스를 독립 제품으로 다시 나눠 범위에서 제외했다. 디자인 시스템은 전 팀 공통으로 통일해 이후 통합 가능성은 남겼다.
- **복잡한 안보다 최소안을 선택했다**: 캔버스 배치안 투표에서는 가장 복잡한 안이 최다 득표였다. 기간 내 구현 가능성을 근거로 최소안을 제안했고, 나머지는 로드맵으로 넘겼다.
- **무효가 될 실험을 막았다**: 참고 이미지를 넣었을 때와 넣지 않았을 때를 비교하기 전 코드를 확인했다. 프론트와 백엔드의 필드명이 달라 이미지가 서버에 도달하지 않는 상태였다. 필드명을 맞춘 뒤 비교 실험을 다시 설계했다.
- **발표 6일 전 산출 구조 변경을 반영했다**: 현업 PD가 이미지 9장을 병렬 생성해 합성하던 방식을 바꿔 달라고 요청했다. 비용 문제로 3×3 그리드 이미지 1장을 한 번에 생성하는 구조로 바꾸는 요청이었다.
- **수정 범위부터 산정했다**: 요청을 바로 코드에 반영하지 않고 바뀌는 영역과 우선순위를 정했다. 계획하던 이미지 품질 개선 테스트는 포기했다. 개발자 3명에게 각자 맡은 파트를 기준으로 바뀌는 점을 나눠 확인했다. QA → 수정 사항 QA → 전체 QA → 시연 순서로 반복하며 발견한 버그를 전달했다.
- **못 고친 문제는 원인을 남겼다**: 컷 간 일관성과 병렬 생성 문제는 기간 안에 해결하지 못했다. 원인을 코드 수준으로 확인해 로드맵과 예상 질문 답변에 정리했다.

## 문서 거버넌스

- **PRD v0.4 → v2.0 버전 체인**: 버전마다 무엇이 왜 바뀌었는지 남겼다. 백엔드 스택 변경 반영 누락과 실제 코드에 없는 모델명도 정정 이력에 기록했다.
- **운영 리듬**: 데일리 회의록에 결정과 커밋·이슈를 맞춰 기록했다. 수정요구사항 핸드오프 문서를 거쳐 개발 전달 체계를 유지했다. 회의록은 28건이다.
- **인계**: PD 요청에 맞춰 제출 범위를 먼저 확정했다. 문서 6종을 작성하고 미해결 항목을 '인계 시점 조치'와 '재배포 시점 과제'로 나눴다.

## 배운 점

시간이 없을수록 PM이 할 일은 **자를 것을 정하고, 검증이 유효한지 먼저 확인하는 것**이었다. 코드를 읽는 능력은 개발 속도보다 **의사결정의 정확도**로 돌아왔다. 필드명 하나를 확인하지 않았다면 팀 전체가 잘못된 근거로 방향을 정했을 것이다.

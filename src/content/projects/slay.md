# SLAY — 일행이 짠 일정을 AI가 검수하는 여행 플랫폼

> **사람이 짠 일정을 외부 데이터로 검수하는 AI를 설계한 4인 캡스톤 팀장**
> `팀장 · 기획 + 풀스택` · `캡스톤 4인팀` · `2025.02–06`

## 🎯 문제

일정은 짜놓고 가는데 현지에서 자꾸 틀어진다. 야외 일정을 잡은 날 비가 오고, 도착하니 브레이크타임이고, 하루 동선이 앞뒤로 왔다 갔다 한다. 여행 앱은 대부분 **일정을 만들어주는 것까지**만 하고, 그 일정이 실제로 말이 되는지는 봐주지 않는다.

그래서 방향을 이렇게 잡았다. **일정은 사람이 짜되, 짠 일정을 AI가 검수한다.**

## 🧭 핵심 — 공동 편집 + AI 검수

- **일정 공동 편집** — 동행을 초대해 같은 일정을 여러 명이 함께 짠다. 드래그앤드롭으로 일자·장소를 재정렬하고 시간을 배정한다
- **AI 검수** — 짜인 일정을 세 가지 축으로 점검하고 문제를 짚어준다

| 점검 축 | 무엇을 보는가 | 어떻게 알려주는가 |
| --- | --- | --- |
| **날씨** | 기상청·OpenWeather 예보와 방문 지역·날짜를 대조 | 날씨가 나쁜 날의 야외 활동에 주의 표시 |
| **영업시간** | Google Places의 영업시간과 방문 예정 시각을 대조 | 브레이크타임·영업 종료와 겹치면 경고 |
| **동선** | 하루 이동 경로의 낭비 구간 | 추천 경로를 제시하고 **반영하기 버튼**으로 일정에 바로 적용 |

## 🛠 그 외 구현

- **친구·동행 초대(협업)** — 친구 요청/수락 + 여행 동행 초대 → 공동 일정 편집
- **경비 입력·1/N 자동 정산** — `/expense/create`·`/settle` + SettleUpModal
- **지도·로드뷰** — Kakao Map. 위성보기를 누르면 로드뷰로 전환
- **여행 기록 갤러리(소셜)** — 게시글·좋아요·댓글
- **AI 챗봇(부가)** — OpenAI 연동 여행지·장소 질의응답, 세션 유지

## 🧱 기술 스택 · 아키텍처

| 구분 | 기술 |
| --- | --- |
| Frontend | React · react-router · @hello-pangea/dnd |
| Backend | Node.js/Express · Prisma ORM · Swagger |
| DB | **PostgreSQL** (13개 도메인 모델 · enum 9종) |
| 인증 | JWT + OAuth2.0 (Google/Naver/Kakao) |
| 외부 API | OpenAI · **Kakao Map**(지도·로드뷰) · **Google Places**(영업시간) · OpenWeather · 기상청 |
| 배포 | **AWS + Nginx** (모노레포 / npm workspaces) |

React(FE) ↔ Nginx → Node.js(+JWT)(BE) ↔ Prisma → PostgreSQL, 외부 API 6종 오케스트레이션.

## 👥 역할 구분

4인 팀의 팀장으로 **제품 방향을 정하고 기능을 나눈 뒤, 협업 영역을 직접 구현**했다.

| 영역 | 내가 맡은 것 | 팀 |
| --- | --- | --- |
| 방향·팀 운영 | **"일정을 만들어주지 말고 검수하자"는 방향 결정** · 레포 개설 · 기능 분담 · 배포 일정 | 아이디어는 4인 공동 |
| **협업 도메인 구현** | **친구·동행 초대, 경비 1/N 정산, 챗봇, 준비물 체크리스트** 네 가지를 설계부터 구현까지 | — |
| AI 검수 기능 | 무엇을 어떤 기준으로 점검할지 정의 | **구현은 팀원이 담당** |
| 운영·배포 | AWS·Nginx 배포와 프록시 장애 대응 | — |
| 추천·지도·리뷰 | — | 팀원 분담 |

> *네 도메인은 코드 라인의 81~100%를 직접 작성했습니다(git blame 확인). 서비스 전체를 혼자 만든 것은 아닙니다. 검수 기능의 날씨·동선 판정 로직과 지도·리뷰는 팀원이 구현했습니다.*

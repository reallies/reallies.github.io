## 사용자와 사용 환경

혼자 거주하는 고령자의 실내 상황을 감지하고, 보호자가 웹에서 확인할 정보로 전달하는 것을 프로젝트 과제로 잡았다. 활동·환경 변화, 외출 중 움직임, 직접 긴급 요청을 하나의 장치에서 다루도록 범위를 정했다. 고령자 본인과 보호자의 행동과 접점을 나눴다.

| 사용자 | 수행하는 행동 | 사용하는 접점 |
| --- | --- | --- |
| 고령자 본인 | 재실·외출 모드 전환, 박수 두 번으로 긴급 요청, 긴급 상태 해제 | 물리 버튼·소리 센서·LED |
| 보호자 | 온습도·마지막 활동·외출 중 촬영 사진과 경고를 확인하고 후속 조치 | 웹 대시보드 |

설치 위치는 입구처럼 사용자의 이동이 잦은 곳을 전제로 했다. 보고서에는 보호자의 알림 확인과 후속 조치가 정상 운영에 필요하다고 명시했다. 자동 감지 후 사람이 확인하는 과정까지 포함한 사용 시나리오다.

## 생활 상황을 감지·대응 규칙으로 정의

재실과 외출에서는 같은 움직임을 다르게 해석하도록 모드를 나눴다. 재실 중에는 활동 시점을 갱신하고, 빈집으로 설정한 외출 모드에서는 사진 촬영으로 연결한다. 긴급 요청은 두 모드 모두에서 받을 수 있도록 별도로 처리한다. 주간인 06:00부터 22:00까지는 장기 미활동을 경고하고, 야간인 22:00부터 다음 날 06:00까지는 감지 시 조명을 반응시키도록 했다.

| 사용 상황 | 감지·입력 조건 | 대응하도록 정한 동작 |
| --- | --- | --- |
| 재실 중 환경 변화 | 온습도가 프로토타입 기준값을 벗어남 | LED로 현장에 경고하고 웹에 온습도 추이 표시 |
| 재실·주간의 장기 미활동 | 마지막 거리 감지 후 2시간 경과 | 보호자가 확인할 수 있도록 웹 경고 전송 |
| 재실·야간 이동 | 움직임 조건 충족 | 시야 확보를 목적으로 노란 LED 반응. 마지막 감지 후 30초가 지나면 소등 |
| 외출 중 움직임 | AWAY 모드에서 움직임 조건 충족 | 카메라로 5장 연속 촬영 후 웹에 전송 |
| 직접 긴급 요청 | 소리 센서 신호가 0.15초 초과·1초 미만 간격으로 두 번 발생 | 빨강·파랑 LED 교차 점멸과 웹의 긴급 팝업 |

박수 두 번을 긴급 요청 동작으로 정했으며, 구현에서는 위의 소리 센서 신호 간격을 사용한다. 박수와 다른 생활 소음을 분류하는 기능은 없다. 움직임은 초음파 거리가 150cm 미만일 때 감지된 것으로 처리한다. 환경 경고 설정값은 고온 30°C 이상, 저온 18°C 이하, 습도 70% 이상이다.

## 보호자가 판단할 정보와 조작 흐름

보호자 화면은 온습도 추이, 마지막 움직임 감지 시각, 최근 촬영 사진, 경고 메시지로 구성했다. 각 정보는 환경 변화, 활동 시점, 외출 중 감지 대상을 확인하는 데 사용한다.

- 온습도는 수신 시점의 값과 최근 추이를 함께 표시한다.
- 활동 정보는 마지막 감지 시각으로 보여준다.
- 외출 중 감지 사진은 최근 6장까지 표시한다.
- 긴급 요청과 장기 미활동은 화면 위 팝업으로 알린다.

웹의 ‘확인’은 팝업을 닫는 동작이다. 장치의 긴급 상태는 물리 버튼으로 해제한다.

웹이 연결된 동안 수신한 온습도를 브라우저 저장소에 기록하고 최근 24시간 범위의 차트를 그린다. 브라우저가 닫힌 동안의 데이터를 서버가 계속 보관하는 구조는 아니다.

## 조건별 시연과 확인 범위

과제 보고서에는 입력 조건을 바꿔 LED·사진·웹 알림으로 이어지는지 시연한 기록을 남겼다.

| 확인할 동작 | 시연 조건 | 보고서에 기록한 결과 |
| --- | --- | --- |
| 고온 경고 | 헤어드라이기 활용 | 노랑·빨강 LED 동시 점멸 |
| 저온 경고 | 창문 개방 | 노랑·파랑 LED 동시 점멸 |
| 고습 경고 | 빨대 활용 | 노란 LED 단독 점멸 |
| 장기 미활동 경고 | 시연을 위해 제한 시간을 2시간에서 10초로 단축 | 웹 경고 팝업 |
| 외출 중 감지 | 버튼으로 AWAY 전환 후 움직임 감지 | 사진 촬영과 웹 전송 |
| 긴급 요청·해제 | 두 번의 박수 후 물리 버튼 입력 | LED·웹 팝업 반응과 장치 긴급 상태 해제 |

## 직접 구현한 범위와 연결 구조

개인 프로젝트로 Raspberry Pi의 센서·GPIO 제어, MQTT 송수신, Flask 기반 웹 대시보드를 구현했다. Python 장치 코드가 센서값과 감지 이벤트를 MQTT 브로커로 발행하고, 브라우저가 WebSocket으로 환경·활동·카메라·경고의 네 토픽을 직접 구독한다. Flask는 대시보드 HTML을 제공한다.

## 구현의 한계와 다음 검증

공개 코드의 알림 경로는 MQTT와 웹 대시보드다. 보호자 문자·앱 푸시는 포함되지 않는다. 야간 조명은 시야 확보를 목적으로 넣은 기능이며 낙상을 판별하지 않는다. 조건별 시연은 기능의 동작 확인으로, 현장 안전성이나 예방 효과를 검증한 결과는 아니다.

입구에서 감지가 없었던 시간을 집 안 전체의 미활동으로 해석할 수 있는지는 별도 확인이 필요하다. 실제 사용을 위해서는 설치 위치와 정상 생활 패턴에 따른 오탐·미탐, 통신 단절, 보호자의 확인·대응 가능성을 검증해야 한다.

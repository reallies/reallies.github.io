2026.11.07 회원 PC 웹을 추가 관찰해 개정했다. 상품 상세의 혜택적용가·차감 내역과 장바구니 미리보기를 확인했다. 계정 식별정보와 전체 보유 잔액은 공개하지 않는다. 실제 결제와 사용자 테스트는 수행하지 않았다.

## 회원 가격을 읽는 세 가지 상태

현대면세점은 회원 상품 상세에서 이미 혜택적용가를 제공한다. 에스트라 듀오세트 1개는 상품 할인가 39,723원 아래에 혜택적용가 28,601원을 표시했고, 펼치면 상품 할인 9,931원과 기본 적립금 예상 사용 11,122원이 따로 보였다.[^F4-01] 이 구조에서 상품 가격, 개인 혜택을 반영한 예상 계산, 최종 주문 적용을 구분하는 원리를 살펴봤다.

장바구니의 최저가 미리보기도 작동했다. 에스트라 1개의 기본 결제예정금액은 $29.60 / 39,723원, 미리보기를 연 상태는 $21.31 / 28,601원이었다. 닫으면 원래 금액으로 돌아왔다.[^F4-03] 핵심 질문은 **예상 계산과 실제 주문 적용의 차이를 어떻게 전달하는가**다. 이 동작이 사용자에게 혼란을 준다고 입증한 것은 아니다.

## 1. 보유한 혜택과 이번 상품에 쓸 수 있는 혜택은 다르다

회원 지갑은 적립금을 종류별로 나누고, 안내에서는 상품·브랜드별 사용 한도와 제외 가능성을 설명한다. 상세 도움말도 기본 적립금과 추가·브랜드·제휴 적립금의 역할을 구분하며 사용률이 상품별로 달라질 수 있다고 안내한다.[^F4-05] 전체 보유액을 곧바로 이번 주문의 차감액으로 읽을 수 없는 구조다.

에스트라 상세에서는 기본 적립금 사용비율 28% 안내와 11,122원의 예상 차감액을 함께 볼 수 있었다. 표시 원화 기준으로 39,723원 − 11,122원 = 28,601원이어서 상세의 두 금액이 어떻게 연결되는지 추적할 수 있다.[^F4-01] 다만 이 한 사례에서 모든 상품의 절사·환산·중복 적용 공식을 확정하지 않았다. 같은 계정의 키엘 125ML 상세는 $34.8 / 46,701원의 혜택적용가와 상품 할인 내역을 표시했으며, 에스트라처럼 별도 적립금 차감이 보인다고 기록하지 않았다.[^F4-02]

**도메인 조건 → 정보 요구:** 혜택은 종류·대상·한도를 가지므로, 개인의 전체 잔액과 상품별 예상 사용액을 구별해야 한다. IA는 지갑의 혜택 목록을 상품의 사용 조건, 해당 금액의 계산 내역과 연결할 이유가 있다.

**현재 패턴과 원리:** 현대면세점은 상세의 짧은 혜택적용가 아래에 차감 내역을 펼치고, 적립금 항목을 한 번 더 펼쳐 종류를 확인하게 한다. 먼저 비교할 금액을 보여주고 필요할 때 근거를 읽는 점진적 공개 방식으로 해석할 수 있다. 실제 제작 의도는 확인하지 않았다.

**대안과 적용 조건:** 모든 조건을 기본 노출하면 한 번에 확인할 수 있으나 상세가 길어진다. 금액만 두면 간결하지만 계산 근거를 따로 찾아야 한다. 기존 펼침 구조를 유지하되 어떤 조건을 먼저 노출할지는 사용자 과업으로 결정한다. 보유액이 충분하다는 이유만으로 한도 없이 적용하지 않는다.

**검증 질문:** 사용자가 전체 보유액과 해당 상품의 예상 사용액을 구별하고, 차감 내역의 근거를 찾는가?

## 2. 미리보기는 주문 적용과 별도의 상태다

회원 장바구니에는 에스트라 1개만 담았다. 미리보기를 열기 전 총주문 기준은 $37 / 49,654원, 예상 차감은 $7.4 / 9,931원, 결제예정금액은 $29.6 / 39,723원이었다. 최저가 미리보기를 열자 예상 차감이 $15.69 / 21,053원으로 바뀌고 예상금액이 $21.31 / 28,601원으로 나타났다. 패널에는 상품 할인과 적립금 예상액이 나뉘어 있었다.[^F4-03]

| 같은 상품·수량의 상태 | 표시된 예상금액 | 확인 범위 |
|---|---|---|
| 상품 할인가·장바구니 기본 상태 | $29.60 / 39,723원 | 상품 할인 표시 |
| 회원 상세 혜택적용가·장바구니 미리보기 열림 | $21.31 / 28,601원 | 기본 적립금 예상 11,122원 포함 |
| 장바구니 미리보기 닫힘 | $29.60 / 39,723원 | 기본 상태로 복귀 |
| 최종 주문 적용·결제 완료 | 미확인 | 여권·출국정보 입력 전에 중단 |

현행 화면은 이 값이 예상이며 최종 결제금액이 달라질 수 있음을 안내한다.[^F4-01][^F4-03] 미리보기를 열었다는 행동을 적립금 사용 확정이나 결제 완료로 해석하지 않는다. 주문하기를 눌렀을 때 여권·출국정보 입력 단계가 열렸고, 정보를 입력하거나 저장하지 않아 뒤의 최종 주문서에는 접근하지 않았다.[^F4-06]

**도메인 조건 → 정보 요구:** 상품 가격, 개인 혜택을 반영한 시뮬레이션, 최종 주문의 금액은 상태가 다르다. UI의 가격 숫자와 그 숫자가 나타내는 상태가 함께 전달돼야 한다.

**현재 패턴과 원리:** 상품 상세는 할인가와 혜택적용가를 나누고, 장바구니는 명시적인 미리보기 행동으로 계산 상태를 전환한다. 기존 계산·차감 내역을 유지하면서 상태 이름과 해제 후 변화가 어떻게 읽히는지 확인할 수 있다.

**대안과 적용 조건:** 기본값과 미리보기를 나란히 놓으면 두 값을 비교하기 쉬워질 수 있지만 화면에 금액이 더 많아진다. 미리보기 하나만 크게 표시하면 단순해지지만 조건과 해제 상태를 설명해야 한다. 어떤 안이 더 낫다는 결론은 현행과 동일한 과업으로 비교한 뒤에 내린다.

**검증 질문:** 미리보기를 열고 닫은 사용자가 현재 보고 있는 금액의 조건을 설명하는가? 미리보기만 보고 혜택 사용이 확정됐다고 답하지 않는가?

## 3. 쿠폰을 볼 수 있는 것과 주문에 적용되는 것은 다르다

에스트라의 쿠폰 받기 버튼은 회원 상태에서 쿠폰 목록 레이어를 열었다. 여기에는 웰니스관 전용 3%, 최소구매 $5 조건과 발급일부터 0일이라는 표시, 다운로드 진입이 있었다.[^F4-04] 기간 표기의 의미나 실사용 가능 여부를 임의로 해석하지 않았다. 다운로드와 실제 쿠폰 적용은 수행하지 않았다.

**도메인 조건 → 정보 요구:** 쿠폰에는 대상·최소금액·유효기간과 중복 조건이 있다. ‘조회 가능한 쿠폰 → 발급된 쿠폰 → 상품에 사용 가능한 쿠폰 → 주문에 적용된 쿠폰’은 같은 상태가 아니다. IA에서 쿠폰 상세 조건과 적용 결과를 연결할 이유가 생긴다.

**현재 패턴과 원리:** 현대면세점은 목록 레이어에서 쿠폰 조건과 다운로드 행동을 함께 제공한다. 상품 상세의 할인율이나 쿠폰 표시만으로 실제 적용 쿠폰을 단정하지 않는다. 이번에 본 20% 할인이 레이어의 3% 쿠폰에서 비롯됐다는 설명도 하지 않는다.

**대안과 적용 조건:** 쿠폰을 모두 자동 발급하면 수령 과업은 줄 수 있지만 적용 자격과 중복 규칙이 해결되는 것은 아니다. 사용 가능한 쿠폰을 먼저 보여주는 경우에도 제외 이유와 전체 목록의 접근을 고려해야 한다. 실제 정책을 확보하기 전에는 자동 최저가나 중복 할인을 약속하지 않는다.

**검증 질문:** 사용자가 쿠폰 목록의 조건과 이번 주문의 적용 결과를 구별하는가? 기간 표기에서 사용 기한을 어떻게 판단하는지 확인할 수 있는가?

## 4. 가격 비교에는 시점과 혜택의 종류를 남긴다

11월 7일 직접 관찰한 환율은 USD 1당 1,342.00원이었다. 같은 날 비로그인 IAB의 에스트라 상세는 상품 할인가 $29.6 / 39,723원과 적립금 비율 안내를 보여줬고, Chrome의 회원 상세에서는 추가로 $21.31 / 28,601원의 혜택적용가를 확인했다.[^F4-01][^F5-01] 서로 다른 브라우저 관찰이므로 로그인 효과만 분리한 통제 실험으로 보지는 않는다.

전날 비로그인 기록의 원화 금액을 이번 회원 금액과 비교해 차이 전체를 로그인 효과라고 설명하지 않았다. 날짜·환율·계정·상품·수량을 함께 기록해야 비교 범위를 알 수 있다.[^F0-01]

상품 상세는 구매에 따른 포인트 적립을 결제 혜택과 별도 항목으로 두고 있었다.[^F4-01][^F4-02] 새로 받을 포인트·캐시백·추첨을 현재 지출에서 임의로 빼지 않는다. 보유 포인트를 사용하는 것과 새로 적립되는 것도 구분한다. 전체 혜택을 한 체감가로 합치는 대안은 실제 결제액과의 차이·지급 조건·시점을 설명해야 한다.

**패턴 선택 원리:** 서비스가 표시한 달러·원화 금액을 함께 기록하고 확인 시점을 남긴다. 원화 차감액의 합은 직접 대조하되, 달러에 환율을 한 번 곱하는 자체 추정식으로 원화 표시를 덮어쓰지 않는다. 정확한 환산·절사 순서는 이번 관찰로 확정하지 않았다.
